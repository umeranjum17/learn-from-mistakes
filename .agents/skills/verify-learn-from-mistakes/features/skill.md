# Agent skill (generated stub, npx discovery)

## Sub-features
`skills/learn-from-mistakes/SKILL.md` is generated by `scripts/build-skill.mjs`
(`npm run build:skill`); `npm run build:skill -- --check` (run by `npm test`)
fails on a stale copy. The skill is a stub that sends the agent to
`npx -y learn-from-mistakes-axi --help` and `guide`; the procedure lives in
`guide`. This verify skill is `metadata.internal`, so `npx skills add --list`
offers only `learn-from-mistakes`.

## How to get to it (user POV)
`npx -y skills add umeranjum17/learn-from-mistakes --skill learn-from-mistakes -g -a claude-code -y`,
then ask the agent "what keeps going wrong in this project? the log is defects.md"
or type `/learn-from-mistakes what keeps going wrong here?`.

## Driving it
1. Check: `npm run build:skill -- --check` exits 0; after a one-character edit
   of SKILL.md it exits 1 and `npm test` fails; `git checkout` the file.
2. npx before publish: in an owned scratch dir run a throwaway Verdaccio on
   127.0.0.1 (anonymous publish for `learn-from-mistakes-axi` only, `**`
   proxied to npmjs), `npm pack`, `npm publish <tgz> --registry http://127.0.0.1:4873/`
   (never the real registry). In an isolated HOME whose `.npmrc` names only that
   registry, with no `learn-from-mistakes-axi` on PATH, run `npx -y
   learn-from-mistakes-axi --version`, `--help`, `guide`, bare (no config:
   exit 2, `next: ... guide`), then the examples journey (`ingest`, label
   files copied in, bare report, `report --full --json`).
3. Agent session: a fresh git project holding only a synthetic 30-60 line
   `defects.md`; install the skill there with `npx -y skills add
   umeranjum17/learn-from-mistakes#<branch> --skill learn-from-mistakes -a
   <claude-code|codex|opencode> -y`; start the agent session with the agent CLI that runs it; in the scratch `LFM_HOME` set `agent`, `judge_agent` and their `agent_config.<agent>.model` yourself (or `init --agent ... --model ...`): the tool picks none; start the agent with
   `npm_config_registry=http://127.0.0.1:4873/`, a scratch `npm_config_cache`
   and `LFM_HOME`, under `script -q --log-timing` in a tmux pane. Send the
   plain ask; in a second fresh project send `/learn-from-mistakes ...`.
   Time from the ask to the final answer with the transcript timestamps.
   PASS when the transcript shows the skill loaded without being named, the CLI
   run only as `npx -y learn-from-mistakes-axi` (guide, ingest, report), every
   record labelled, and the answer names a repeated cause with counts.

## Gotchas
Evidence (typescripts, frames, transcripts, timings) stays in the caller's
private evidence folder, never the repo. Use synthetic logs only. The host
Claude has its own user-level skills: confirm none is a learn-from-mistakes
skill before claiming discovery came from the installed stub. `npx skills add`
needs `owner/repo#branch` for a branch with a slash. The Claude trust dialog
defaults to "No, exit". npm publish needs the captain's word.
